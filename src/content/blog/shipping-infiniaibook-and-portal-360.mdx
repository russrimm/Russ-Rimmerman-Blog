Seven weeks later, its <Term def="The folder, tracked by a tool called Git, that holds a project's files and the full history of every change.">repository</Term> has 252 commits and more than 60,000 lines of code, and the app does things I hadn't planned when I started: it imports Microsoft Learn pages, narrates animated explainers, and coaches you through other apps by looking at your screen. ## What's new in InfiniAIBook

My field guide, [InfiniAIBook: A Self-Hosted AI Research Notebook](/blog/open-notebook-self-hosted-research-notebook/), explains how the app works and was last updated on October 23. These are the changes since then, grouped by theme.

### Microsoft Learn as a source, and as live context

Open **Add sources → Microsoft Learn** to search official documentation and import full pages, not just snippets. The search runs through the public Microsoft Learn <Term def="A small service that gives AI apps a standard way to reach outside tools and data.">Model Context Protocol ("MCP") server</Term>, so there's no extra key to configure. The app's server only needs to be able to reach `learn.microsoft.com` over the internet.

There are two ways to use it:

- **Import pages.** Selected pages become saved sources, indexed like any other, so chat, Studio, live discussions, and library-wide search can all use them. A page already in the notebook is marked, and duplicates are refused.
- **Use live Microsoft Learn in chat.** This is a per-notebook switch, off by default. Each new question searches Learn for fresh passages alongside only the saved sources you ticked. Live results don't become sources. Their citations open the exact excerpt that was used, with a link to the original page, and that excerpt stays with the answer even if the page changes later.

Live mode applies to notebook chat only, so import the pages if you want Studio or live discussions to use them. If Learn can't be reached, chat says so instead of quietly dropping it. Separately, **Search web** now tries Bing's public <Term def="A feed format that lets tools read a website's new content automatically.">Really Simple Syndication ("RSS")</Term> search first and falls back to any search keys you've configured.

### A guided start, and a Sources panel that stays out of the way

A new notebook opens with a three-step guide in the chat panel: **Add sources**, **Choose sources**, and **Open Studio**. It's a stepper rather than a checklist. The rail shows what's done, **Back**, **Next**, or a click on the rail moves between steps, and adding or ticking a source advances it for you.

### Training videos: animation controls and visible progress

Training videos picked up three changes on October 26 and 27.

**Animation controls.** Under **Design → Animation**, choose **None**, **Light (transitions only)**, or **Full**, then fine-tune four toggles: transitions and fades, slow push-ins on pictures, bullets that appear one at a time, and the presenter gliding between layouts. The setting applies to the in-browser preview and the exported MP4, and changing only animation recomposes the video without rendering the presenter again.

**Progress and failures.** Composing a training video now shows a progress bar, the motion explainer's animation step shows a percentage, and a failed training-video render names the preparation step that failed.

### An optional second renderer: HyperFrames

A <Term def="The part of an app that turns a script and pictures into a finished video file.">renderer</Term> turns a script and pictures into video, and InfiniAIBook has always had one written in Python. You can now switch motion explainers and training videos to [HyperFrames](https://github.com/heygen-com/hyperframes), an open-source tool that builds the video as an animated web page and renders it frame by frame in a copy of Chrome that runs without a window.

It's opt-in. Add `MOTION_RENDERER=hyperframes` or `TRAINING_RENDERER=hyperframes` to your `.env.local` file (the private settings file that stays on your computer), and only the last rendering step changes. In training videos, captions become real text, so they render sharper. If HyperFrames can't run, InfiniAIBook falls back to its built-in renderer and the video's note says so. It needs <Term def="A free command-line tool that converts and combines audio and video.">ffmpeg</Term> installed and downloads Chrome the first time it runs, and the <Term def="A tool that packages an app and everything it needs into one unit, called a container, so it runs the same way on any machine.">Docker</Term> image doesn't include HyperFrames or Chrome.

### Smaller changes worth knowing

- **Help and About, refreshed.** The **? Help** button opens grouped, expandable topics for every workflow, with links to the full docs. About carries the MIT license notice and the third-party notices.
- **YouTube transcript recovery.** When a video has no public captions, the import message points to the Gemini setting as the recovery path and explains what browser cookies can and can't do.
- **Spending ceiling coverage.** The daily ceiling now reserves budget for avatar rendering, scales speech and chat estimates by size, and applies by default whenever paid Azure AI Speech is configured.
- **An agent skill.** A <Term def="A reusable set of instructions that an AI coding assistant loads when a task matches.">skill</Term> teaches GitHub Copilot, Claude Code, Codex, or Cursor how to install, configure, and script the app.

<Screenshot
  src={helpTopics}

  caption="The refreshed Help dialog, grouped by task. Each topic expands in place and links to the full docs."

The skill is plain <Term def="A simple way to write formatted text using ordinary characters, such as a # to mark a heading.">Markdown</Term> with no scripts. One command installs it, and the `skills` tool asks which of your coding assistants should get it:

```bash
npx skills add russrimm/InfiniAIBook --skill infiniaibook
```

It also tells the agent to keep keys in `.env.local`, leave the server on `127.0.0.1`, and confirm before bulk generation.

### Structure explorer for data files

For structured data files, **Explore structure** opens a tree and graph or a table with types and counts. It works with JavaScript Object Notation ("JSON"), Extensible Markup Language ("XML"), comma-separated values ("CSV"), and tab-separated values ("TSV") files. ## What's new in Portal 360°

Portal 360° is the private admin console I covered in [Portal of Portals: One Console for Every Admin Portal](/blog/portal-of-portals-deep-dive/) and the [project page](/projects/portal-of-portals/). That deep dive was last updated on August 1. Since then the <Term def="The primary line of a project's history, which every finished change is merged into.">main branch</Term> has gained roughly 2,000 commits, and the app now has about 460 pages and more than 900 <Term def="The behind-the-scenes web addresses an app uses to read data or make changes, separate from the pages you see.">API routes</Term> behind them. Portal 360° manages a Microsoft <Term def="Your organization's own instance of Microsoft cloud services, tied to its directory of users and apps.">tenant</Term>, so most of these changes are for the administrators who run one. Here is what I'd point to, grouped by area.

### Home, navigation, and people

- The home page now has **Menu** and **Tenant Pulse** tabs, a near-black dark theme, and a slim **Needs attention** panel instead of a tall one.
- Microsoft Foundry has its own group in the left navigation.
- Every table that has a column picker uses the same **Columns** button, and wide tables pin a scrollbar to the bottom edge.
- Microsoft Teams presence shows as a badge beside people's names across the portal, and a name opens that person's workspace.

### Copilot adoption and licensing

- You can search Copilot interactions by agent.
- Copilot Studio licensing reports, with Copilot Credit consumption charts added to the licensing reports.
- **License Optimization** ranks waste findings, lets you exclude users or groups, and supports a bulk reclaim of eligible seats.

Keyboard-only use and pages at 200% and 400% zoom now have automated checks. This is the part of the work I spend the most time reviewing.

Lines include tests and blank lines. TypeScript and Python are the programming languages the two apps are written in. Comparing August 1 to today, Portal 360°'s TypeScript shows roughly 360,000 lines added and 87,000 removed.

Lines of code are a poor measure of value, and I'm quoting them only to show how little the typing costs now. The cost that remains is judgment. I plan before Copilot writes anything, and I read what it produces. Automated <Term def="Small programs that run the app's code and check that it still does what it should, so a mistake shows up before anyone uses it.">tests</Term> run before changes merge, and they do catch things: recently, two changes that each passed on their own broke the main branch's checks when they landed together. The fix landed as a pull request like any other.

I can't read 685,000 lines, and nobody can. What I can do is decide what to build, test it against a real tenant, run security reviews, and decide what's good enough to ship. Those skills matter more now, not less.

One more detail. InfiniAIBook's repository includes a [recreation prompt](https://github.com/russrimm/InfiniAIBook/blob/main/docs/recreation-prompt.md) that asks a coding assistant to rebuild the app from an empty folder, and the repository says plainly that it hasn't been tested end to end. The idea holds up anyway: if you can describe a product precisely enough for a model to rebuild it, you understand it. That precision is the skill I'd practice if I were starting over.

I keep coming back to who this opens up. For most of my career, "I have an idea for a tool" ended at "and I'd need a developer." A teacher who wants a study aid, a nonprofit coordinator who needs a tracker, or a clinic manager who needs an intake form can now describe the thing and have a first version the same week. When more people can build the tools they need, more problems get solved by the people closest to them. I'm optimistic about what that does for all of us.

The caution is the one I'd give anyone. Speed raises the stakes on judgment. Read what the AI writes, test it, and keep sensitive data out of anything you haven't reviewed. The [vibe-coding lessons](/blog/vibe-coding-lessons/) I wrote earlier cover the habits that help.
