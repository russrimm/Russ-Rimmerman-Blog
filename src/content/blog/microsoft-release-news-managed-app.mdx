Every team has someone who keeps up with what's changing in the products they depend on. It's usually a side job. They read a roadmap in one tab, an announcement in another, and a blog post in a third, then summarize it for everyone else.

That kind of small, specific need almost never gets a developer's time. It's too small for a project and too useful to ignore. I wanted to see what happens if the person with the need simply asks for the app.

So I did. I built Microsoft Release News as a managed app in Copilot Studio, and this post is about that experience more than about the app. It's my own app, not an official Microsoft news service, and the Copilot Studio app builder is currently in preview.

## One sentence, one working app

The request in my build conversation was:

> I want to display all Microsoft release news in a single pane of glass

That's an outcome, not a design. I didn't pick controls, sketch a layout, or describe a data structure. The builder asked what it needed to, then put a working preview next to the conversation.

This is the part I'd want a non-developer to notice. You don't need to know what a component, a connector, or a framework is. You describe the job, look at what comes back, and say what to change. [Microsoft's app creation guide](https://learn.microsoft.com/en-us/microsoft-copilot-studio/apps-experience/create-app) describes the same loop: explain the problem, answer follow-up questions, try the preview, and ask for adjustments.

What came back is a real application with four source tabs, search, and product grouping. That's far more than I specified, and I could have asked for more.

## What it gives the organization

The value isn't the screen. It's that a question that used to take several tabs and a person's afternoon now has one place to start.

| Azure Updates | Azure product releases, previews, and retirements |

## Building costs credits, running doesn't

Here's the cost detail that matters if you're thinking about sharing an app like this widely.

Building a managed app consumes Copilot Credits. Running it is a separate question. Per Microsoft's [licensing and Copilot Credits guidance](https://learn.microsoft.com/microsoft-365/admin/manage/apps/licensing-credits), each person who runs the app needs either a Power Apps Premium license or coverage through a spending policy that includes Copilot Managed Runtime. If a user has a Power Apps Premium license, their normal use of the app doesn't consume Copilot Credits.

A few caveats from that same guidance:

- Sharing an app gives people access, but it doesn't cover the cost of running it. A Microsoft 365 Copilot license alone doesn't cover it either.
- Users without Power Apps Premium can run apps through a spending policy, which charges Copilot Credits per API call.
- Premium-licensed users can still incur credits for specialized services or for usage above the daily request limits, though the guidance calls that unlikely.

So for a team that already has Power Apps Premium assigned, the ongoing cost of an app like this is mostly the build, not each person opening it. Your admin can confirm how your organization is set up.

## Message Center has a different access boundary

The Message Center tab reads an organization's own notices, so it behaves differently from the public tabs. Microsoft documents these as [service update messages for a tenant](https://learn.microsoft.com/en-us/graph/api/serviceannouncement-list-messages?view=graph-rest-1.0), and reading them through Microsoft Graph requires the relevant permission.

The [Copilot Studio apps overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/apps-experience/apps-overview) covers the broader rule: connected organizational data uses the signed-in user's identity, and sharing an app doesn't give someone access to data they couldn't otherwise read. That's why I'm showing the public roadmap here and not organization-specific notices. My running instance isn't a public demo.

## Before you try it

"Managed" here means the app runs on Microsoft-hosted infrastructure for identity, approved connectivity, and governance, so you aren't standing up a website to try an idea. The [Copilot Managed Runtime admin overview](https://learn.microsoft.com/en-us/microsoft-365/admin/manage/apps/) covers app inventory in the Microsoft 365 admin center and controls over distribution and usage.

Two things to check first. Copilot Studio's app experience is rolling out gradually, and administrators can disable app creation. And Microsoft identifies this as a preview experience, not one intended for production use, so it's a good fit for experiments and low-risk internal tools before you rely on it for a business process.

## Start with the smallest useful job

I took the same describe-and-preview approach with an [Excel compliance tracker turned into a managed app](/blog/excel-compliance-calendar-managed-app/). Different task, same pattern: say what you need, check the preview, refine it.

If you're curious, pick one recurring job you can describe in a sentence, like "show me what changed for the products my team uses." Ask for it, try the preview, and see whether it's useful before widening the scope. If it is, you've given your team something real, and you didn't need to write a line of code to get there.
